## 📊 2. Rubrics

### Contribution-Based Rubric
**File**: [`../rubrics/contribution-based.md`](../rubrics/contribution-based.md)

**What It Is**:
A comprehensive grading rubric using open-source contribution standards.

**Categories** (100 points total):
1. **Relevance & Scope** (25%) - Problem-solving appropriateness
2. **Code Quality & Tests** (25%) - Clarity, maintainability, coverage
3. **Documentation & Communication** (20%) - README, PR descriptions, comments
4. **Collaboration & Git Hygiene** (15%) - Commits, reviews, issues
5. **AI Disclosure & Reflection** (15%) - Transparent AI use, learning evidence

**What's Included**:
- Detailed criteria for each level (Exceptional to Needs Work)
- Evidence to look for
- Self-assessment checklist (25 items)
- Example PR descriptions and commits
- Grade conversion table
- Tips for students and instructors

**How to Use**:
1. Share with students at assignment start
2. Use GitHub PR review features for feedback
3. Check contribution graphs and insights
4. Provide specific, rubric-aligned feedback

**Customization Options**:
- Adjust point distribution
- Add/remove categories
- Modify level definitions
- Create simplified versions for intro courses

---

### Simplified Rubric (3 Categories)
**Recommended for**: Introductory courses

**Categories**:
1. **Functionality** (40%) - Does it work?
2. **Code Quality** (40%) - Is it readable and tested?
3. **Documentation** (20%) - Can others understand it?

### Common Questions

**Q: Students don't have GitHub accounts**  
A: GitHub is free; can sign up in minutes. Consider doing in-class setup session.

**Q: Codespaces quota exceeded**  
A: Apply for education benefits, use public repos, or provide local setup instructions.

**Q: Students confused by Git**  
A: Provide simple workflow guide, use GUI options, demo in class.

**Q: How do I grade the "learning" not just the output?**  
A: Require reflections, check git history, value process documentation.
