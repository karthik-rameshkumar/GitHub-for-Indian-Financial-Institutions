# Contribution-Based Rubric for Open-Source Style Projects

> **Purpose**: Assess student work using open-source contribution standards  
> **Applies to**: GitHub-based assignments, projects, and collaborative work  
> **Total Points**: 100

## 📊 Overview

This rubric evaluates student contributions using the same criteria that open-source projects use to assess contributions. It emphasizes not just code correctness, but also communication, collaboration, documentation, and transparent use of AI tools.

## 🎯 Grading Criteria

### 1. Relevance & Scope (25 points)

**Does the contribution solve the right problem in an appropriate way?**

| Points | Level | Criteria |
|--------|-------|----------|
| 23-25 | Exceptional | • Addresses core requirements perfectly<br>• Scope is well-defined and appropriate<br>• Solution is elegant and minimal<br>• Goes beyond requirements thoughtfully |
| 20-22 | Proficient | • Meets all stated requirements<br>• Appropriate scope for the problem<<br>• Solution is effective and clear<br>• Some thoughtful enhancements |
| 17-19 | Developing | • Meets most requirements<br>• Scope is mostly appropriate<br>• Solution works but could be simpler<br>• Few enhancements beyond basics |
| 14-16 | Basic | • Meets some requirements<br>• Scope is too broad or too narrow<br>• Solution is overly complex or incomplete<br>• Minimal effort beyond requirements |
| 0-13 | Needs Work | • Missing key requirements<br>• Inappropriate scope<br>• Solution doesn't address the problem<br>• No consideration of requirements |

**Evidence to Look For**:
- Issue/PR clearly states what problem is being solved
- Changes are focused and don't include unrelated modifications
- Solution complexity matches problem complexity
- Tests cover the relevant functionality

---

### 2. Code Quality & Tests (25 points)

**Is the code clear, maintainable, and well-tested?**

| Points | Level | Criteria |
|--------|-------|----------|
| 23-25 | Exceptional | • Code is clean, readable, and follows conventions<br>• Comprehensive test coverage (>90%)<br>• All tests pass (CI green)<br>• Handles edge cases thoughtfully<br>• Excellent error handling |
| 20-22 | Proficient | • Code follows most conventions<br>• Good test coverage (>75%)<br>• Tests pass consistently<br>• Handles main edge cases<br>• Adequate error handling |
| 17-19 | Developing | • Code is functional but inconsistent style<br>• Basic test coverage (>50%)<br>• Most tests pass<br>• Some edge cases covered<br>• Basic error handling |
| 14-16 | Basic | • Code works but hard to read<br>• Minimal testing (<50%)<br>• Tests may be failing<br>• Edge cases not considered<br>• Poor error handling |
| 0-13 | Needs Work | • Code is poorly structured<br>• No tests or tests don't run<br>• Failing tests not fixed<br>• No error handling<br>• Doesn't follow any conventions |

**Evidence to Look For**:
- GitHub Actions CI status (green checkmark)
- Test files present and comprehensive
- Code follows language/framework conventions
- Meaningful variable and function names
- Comments where needed (but not over-commented)

---

### 3. Documentation & Communication (20 points)

**Can others understand and use this contribution?**

| Points | Level | Criteria |
|--------|-------|----------|
| 19-20 | Exceptional | • Excellent README with examples<br>• Clear PR description with context<br>• Code comments where helpful<br>• Links to relevant issues/docs<br>• Screenshots/demos for visual changes |
| 17-18 | Proficient | • Good README covering basics<br>• PR description explains changes<br>• Adequate code comments<br>• References related work<br>• Some visual aids |
| 14-16 | Developing | • Basic README present<br>• PR description is brief but clear<br>• Minimal code comments<br>• Few references<br>• Limited visual aids |
| 11-13 | Basic | • Minimal README<br>• Vague PR description<br>• Very few comments<br>• No references<br>• No visual aids |
| 0-10 | Needs Work | • No README or PR description<br>• No comments<br>• Cannot understand the changes<br>• No context provided |

**Evidence to Look For**:
- README.md exists and is informative
- PR description uses template and explains "why"
- In-code comments explain complex logic
- References to issues, documentation, or resources
- Screenshots or GIFs for UI changes

---

### 4. Collaboration & Git Hygiene (15 points)

**Does the contribution follow collaborative development practices?**

| Points | Level | Criteria |
|--------|-------|----------|
| 14-15 | Exceptional | • Clean, atomic commits with clear messages<br>• Responsive to feedback in PR reviews<br>• Uses issues to track work<br>• Helps review others' work<br>• Follows branch naming conventions |
| 12-13 | Proficient | • Clear commit messages<br>• Responds to review feedback<br>• References issues appropriately<br>• Participates in reviews<br>• Mostly follows conventions |
| 10-11 | Developing | • Adequate commit messages<br>• Some response to feedback<br>• Basic issue tracking<br>• Limited review participation<br>• Some convention following |
| 7-9 | Basic | • Vague commit messages<br>• Minimal feedback response<br>• Poor issue tracking<br>• No review participation<br>• Ignores conventions |
| 0-6 | Needs Work | • No meaningful commits<br>• Doesn't respond to feedback<br>• No issue tracking<br>• No collaboration<br>• Disorganized git history |

**Evidence to Look For**:
- Commit history shows logical progression
- Commit messages follow format (e.g., "feat: add login functionality")
- PR conversations show engagement
- Comments on other PRs
- Proper use of branches (not committing to main)

---

### 5. AI Disclosure & Reflection (15 points)

**Is AI use transparent and has it enhanced learning?**

| Points | Level | Criteria |
|--------|-------|----------|
| 14-15 | Exceptional | • Detailed AI assistance declaration<br>• Includes prompts and responses<br>• Thoughtful reflection on learning<br>• Clear modifications to AI suggestions<br>• Evidence of critical evaluation |
| 12-13 | Proficient | • Complete AI disclosure<br>• Some prompts/responses included<br>• Good reflection on use<br>• Shows modifications made<br>• Some critical thinking |
| 10-11 | Developing | • Basic AI disclosure present<br>• Minimal prompts/responses<br>• Brief reflection<br>• Few modifications noted<br>• Limited critical evaluation |
| 7-9 | Basic | • Incomplete AI disclosure<br>• No prompts/responses<br>• Vague reflection<br>• Unclear modifications<br>• No critical thinking shown |
| 0-6 | Needs Work | • No AI disclosure (if AI was used)<br>• No documentation of AI use<br>• No reflection<br>• Appears to be unmodified AI output |

**Evidence to Look For**:
- "AI Assistance Declaration" section in README or PR
- Examples of prompts given to AI tools
- Explanation of what was learned
- Documentation of how AI output was modified
- Comments in code indicating AI-assisted sections

| Category | Points | Weight |

| 73-76 | C | Acceptable work, several gaps |
| 70-72 | C- | Minimal acceptable work |

## 🎯 Using This Rubric

### For Students

**Before Starting**:
1. Review all five categories to understand expectations
2. Check examples of excellent work (if provided)
3. Set up your repository with proper structure
4. Plan for documentation and testing from the start

**During Development**:
1. Make frequent, small commits with clear messages
2. Write tests as you write code
3. Document as you go (don't save it for the end)
4. Track your AI use immediately when it happens
5. Engage with issues and PRs

**Before Submission**:
1. Run all tests and ensure CI passes
2. Complete README with all sections
3. Write comprehensive PR description
4. Add AI disclosure section
5. Self-review against this rubric

### For Instructors

**Setup**:
1. Share this rubric at assignment start
2. Provide examples of A-level work
3. Create a GitHub Classroom assignment
4. Set up GitHub Actions for automated testing

**During Assessment**:
1. Use GitHub's PR review features for feedback
2. Comment on specific lines of code
3. Run automated checks (tests, linters)
4. Check contribution graphs and insights
5. Review issue and PR participation

**Feedback**:
1. Provide specific, actionable feedback
2. Point to rubric categories
3. Highlight what was done well
4. Suggest concrete improvements
5. Encourage iteration and resubmission (if policy allows)

## 📋 Self-Assessment Checklist

Before submitting, check off each item:

### Relevance & Scope
- [ ] My PR addresses the stated requirements
- [ ] The scope is appropriate (not too big, not too small)
- [ ] I haven't included unrelated changes
- [ ] The solution is as simple as it can be

### Code Quality & Tests
- [ ] All tests pass (GitHub Actions green)
- [ ] Test coverage is >75% (check with coverage tool)
- [ ] Code follows language conventions
- [ ] Edge cases are handled
- [ ] No linting errors

### Documentation & Communication
- [ ] README.md is complete and helpful
- [ ] PR description explains what and why
- [ ] Code has comments where needed
- [ ] I've linked related issues
- [ ] Visual changes have screenshots

### Collaboration & Git Hygiene
- [ ] Commit messages are clear and descriptive
- [ ] I've responded to all review comments
- [ ] I've used issues to track my work
- [ ] I've reviewed at least one other PR
- [ ] Branch name follows conventions

### AI Disclosure & Reflection
- [ ] AI Assistance Declaration is complete
- [ ] I've included example prompts and responses
- [ ] I've explained what I learned
- [ ] I've documented modifications to AI suggestions
- [ ] AI-assisted code has comments

If you have <20 checks, review those items before submitting!

## 💡 Examples

### Excellent PR Description (20/20 for Documentation)

```markdown
## What
Implements user authentication using JWT tokens (closes #42)

## Why
Users need a way to securely log in and maintain sessions across page reloads.

## How
1. Created JWT token generation on login
2. Added middleware to verify tokens on protected routes
3. Implemented token refresh mechanism
4. Added logout functionality to clear tokens

## Testing
- [x] All existing tests pass
- [x] Added 12 new tests for auth flows
- [x] Manually tested in browser
- [x] Coverage: 87% → 92%

## Screenshots
[Login screen screenshot]
[Protected page with user menu]

## AI Assistance
Used GitHub Copilot to generate initial JWT verification middleware.
Modified to add custom error handling and logging.
See `auth.js` lines 45-60 for details.

## Related
- Addresses #42
- Related to #38 (password reset)
- Uses library suggested in #40
```

### Good Commit Messages (13/15 for Collaboration)

```
✅ feat: add JWT-based authentication
✅ test: add tests for login flow
✅ fix: handle expired tokens gracefully
✅ docs: update README with auth setup
✅ refactor: extract token validation to helper

❌ update code
❌ fixes
❌ WIP
```

### Excellent AI Disclosure (15/15 for AI Use)

```markdown
## AI Assistance Declaration

### Tools Used
- GitHub Copilot (VS Code extension)
- ChatGPT 4 (for algorithm explanation)

### How AI Helped

1. **JWT Middleware (lines 45-60 in auth.js)**
   - Prompt: "Create Express middleware to verify JWT tokens"
   - Used: Basic structure
   - Changed: Added custom error responses and logging

2. **Test Cases (tests/auth.test.js)**
   - Prompt: "Generate test cases for JWT authentication"
   - Used: Test structure ideas
   - Changed: Added edge cases for expired/invalid tokens

3. **Algorithm Understanding**
   - Asked ChatGPT: "Explain how JWT token refresh works"
   - Learned: Why refresh tokens are separate from access tokens
   - Applied: Implemented dual-token system

### What I Learned
- JWT structure (header, payload, signature)
- Why token expiration is important for security
- How to handle token refresh without re-login
- Testing authentication flows

### Critical Evaluation
- AI-suggested storing tokens in localStorage
- I changed to httpOnly cookies for better security
- Researched XSS vulnerabilities before deciding
```

## 🔄 Rubric Variants

### Simplified Version (for introductory courses)

Focus on 3 main categories:
1. **Functionality** (40%): Does it work? Are requirements met?
2. **Code Quality** (40%): Is it readable? Are there tests?
3. **Documentation** (20%): Can others understand it?

### Advanced Version (for senior projects)

Add these categories:
1. **Architecture** (10%): System design quality
2. **Performance** (10%): Efficiency and optimization
3. **Security** (10%): Vulnerability awareness
4. **Innovation** (5%): Creative problem-solving
